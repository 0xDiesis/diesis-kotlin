**The Kotlin SDK for Diesis**

Typed argument, event, error, and tuple classes, selectors, and ABIs for every
public Diesis system contract, plus their fixed addresses and the chain
definitions. Built on
[web3j](https://github.com/LFDT-web3j/web3j), and usable from Java as well as
Kotlin.

Chain ID `1980` · Token **DS** · Runtime **web3j 6** · JVM **21+**

_Greek δίεσις: the smallest interval in music.<br>Diesis aims for the smallest interval between blocks._

</div>

---

## Why this SDK

Diesis builds trading, fee sponsorship, names, staking, and private transfers
into the chain itself, as system contracts at fixed addresses. This package
gives a JVM service the addresses, chain data, and typed classes for those
contracts, so you don't copy hex strings or guess struct fields.

- Every system contract and precompile address ships as an EIP-55 constant.
- `DiesisContracts` pairs the 28 fixed-address contracts with their addresses
  and ABIs, with the same keys as `diesisContracts` in the
  [TypeScript SDK](https://github.com/0xDiesis/diesis-js).
- The objects in `xyz.diesis.contracts` are generated by abi-typegen from the
  Solidity sources, the same source as the TypeScript and
  [Python](https://github.com/0xDiesis/diesis-py) SDKs.
- All three SDKs test their addresses and chain data against the same
  `canonical.json`.

## Install

**In short.** The package is not on Maven Central yet. Build it from a pinned
commit into your local Maven repository, then depend on it.

**Details.** You need JDK 21 and authenticated Git access. The build uses the
Gradle wrapper in the repository, so no separate Gradle install is needed.

```bash
git clone https://github.com/0xDiesis/diesis-kotlin.git
cd diesis-kotlin
git checkout <commit>
./gradlew publishToMavenLocal
```

```kotlin
// build.gradle.kts
repositories {
    mavenLocal()
    mavenCentral()
}

dependencies {
    implementation("xyz.diesis:diesis:0.1.0")
}
```

The artifact is `xyz.diesis:diesis:0.1.0`. It exposes `org.web3j:core` 6.0.0 as
an API dependency, so you don't need to declare web3j yourself.

## Connect

**In short.** You make a normal web3j client and point it at a Diesis node.

**Details.** `DiesisChains.diesis` and `DiesisChains.diesisTestnet` carry the
chain ID, name, native currency, RPC URL, and explorer URL. The chain ID is a
`Long`, which is what web3j's transaction managers take.

```kotlin
val web3j = Web3j.build(HttpService(DiesisChains.diesis.rpcUrl))
```

| Network        | Chain ID | Export                       |
| -------------- | -------- | ---------------------------- |
| Diesis Mainnet | 1980     | `DiesisChains.diesis`        |
| Diesis Testnet | 19803    | `DiesisChains.diesisTestnet` |

## Read a value

**In short.** You describe the function call with web3j, and the SDK sends it
to the contract's fixed address and decodes the answer.

**Details.** Each contract has a generated object in `xyz.diesis.contracts`
with the same name, such as `DiesisStaking`. Inside it, each function that
takes arguments has a `<Function>Params` class, such as
`DiesisStaking.UnclaimedRewardsParams`. Its fields have the Solidity argument
names in order. Integers of any width are `BigInteger`, `address` is `String`,
fixed bytes are web3j types like `Bytes32`, and Solidity structs are tuple
classes that extend web3j's `StaticStruct` or `DynamicStruct`, so you can pass
them to a `Function` as they are. You wrap the other fields in web3j ABI types
to build a `Function`. The object also has each function's canonical signature
and selector, such as `DiesisStaking.UNCLAIMED_REWARDS_SELECTOR`.
`DiesisContract.call` runs it with `eth_call` at the contract's address and
returns the decoded outputs. It throws `DiesisCallException` if the call
reverts.

```kotlin
val params = DiesisStaking.UnclaimedRewardsParams(tokenId = BigInteger.valueOf(42))
val unclaimedRewards = Function(
    "unclaimedRewards",
    listOf(Uint256(params.tokenId)),
    listOf(object : TypeReference<Uint256>() {}),
)
val rewards = DiesisContracts.staking.call(web3j, unclaimedRewards)[0].value as BigInteger
```

`call` also takes an optional `from` address and block parameter.

## Send a transaction

**In short.** You sign with your key, and the SDK sends the call to the right
contract.

**Details.** `DiesisContract.send` encodes the `Function` and passes it to any
web3j `TransactionManager` with the contract's address, then returns the
transaction hash. Use `RawTransactionManager` with the chain ID so the
signature is only valid on Diesis. `value` is in wei, and a payable function
like `stake` needs it.

```kotlin
val params = DiesisStaking.StakeParams(toValidatorId = BigInteger.ONE)
val stake = Function("stake", listOf(Uint256(params.toValidatorId)), emptyList())

val credentials = Credentials.create("0x...")
val transactionManager = RawTransactionManager(web3j, credentials, DiesisChains.diesis.id)

val txHash = DiesisContracts.staking.send(
    transactionManager,
    stake,
    gasPrice = web3j.ethGasPrice().send().gasPrice,
    gasLimit = BigInteger.valueOf(300_000),
    value = Convert.toWei("100", Convert.Unit.ETHER).toBigIntegerExact(),
)
```

## Decode events

**In short.** When a contract emits an event, you can turn the log into a
typed object.

**Details.** Each event has an `<Event>Event` class in its contract's object,
such as `DiesisStaking.StakedEvent`, and a `<EVENT>_EVENT_TOPIC` constant with
its topic 0. You match the log on that topic, then decode it with web3j.
Indexed fields come from `topics`, and the rest from `data`.

```kotlin
fun decodeStaked(log: Log): DiesisStaking.StakedEvent? {
    if (log.topics[0] != DiesisStaking.STAKED_EVENT_TOPIC) return null
    val data = FunctionReturnDecoder.decode(log.data, Utils.convert(listOf(object : TypeReference<Uint256>() {})))
    return DiesisStaking.StakedEvent(
        delegator = FunctionReturnDecoder.decodeAddress(log.topics[1]),
        toValidatorId = BigInteger(log.topics[2].removePrefix("0x"), 16),
        tokenId = BigInteger(log.topics[3].removePrefix("0x"), 16),
        amount = data[0].value as BigInteger,
    )
}
```

Custom errors have `<Error>Error` classes and `<ERROR>_ERROR_SELECTOR`
constants in the same object. An error without arguments is a `data object`.

## Use from Java

**In short.** Everything above works from Java with static fields.

**Details.** Addresses are `static final String` constants. Chains and
contract table entries are static fields on `DiesisChains` and
`DiesisContracts`, and `DiesisContracts.byKey` is a static method. Generated
classes are nested in their contract's object, so Java names them
`DiesisStaking.UnclaimedRewardsParams`. Their fields are read with getters, and
selectors, topics, and `JSON` are static fields.

```java
DiesisStaking.UnclaimedRewardsParams params =
        new DiesisStaking.UnclaimedRewardsParams(BigInteger.valueOf(42));
Function unclaimedRewards = new Function(
        "unclaimedRewards",
        List.of(new Uint256(params.getTokenId())),
        List.of(new TypeReference<Uint256>() {}));

Web3j web3j = Web3j.build(new HttpService(DiesisChains.diesis.getRpcUrl()));
DiesisContract staking = DiesisContracts.staking;
BigInteger rewards = (BigInteger) staking.call(web3j, unclaimedRewards).get(0).getValue();
String spotBook = DiesisAddresses.DIESIS_SPOT_BOOK;
long chainId = DiesisChains.diesisTestnet.getId();
String selector = DiesisStaking.UNCLAIMED_REWARDS_SELECTOR;
```

## Addresses and contract table

**In short.** Diesis system contracts live at fixed addresses that start with
`0xD1E515`. The SDK has all of them, and a table that says which contract
lives where.

**Details.** `DiesisAddresses` holds every system contract and precompile
address from `canonical.json` as an EIP-55 string, and `DiesisAddresses.ALL`
maps constant names to addresses. `DiesisContracts` has one `DiesisContract`
per fixed-address contract with its `key`, `contractName`, `address`, and
`abi`. `contractName` is the name of the generated object that holds the
contract's classes, and `abi` is that object's `JSON` ABI string.
`IValidatorShare` has no fixed address, so it has a generated object but no
table entry.

```kotlin
val staking = DiesisContracts.staking
println("${staking.key} ${staking.contractName} ${staking.address}")
val abiJson: String = staking.abi

for (contract in DiesisContracts.ALL) {
    println("${contract.key} -> ${contract.address}")
}

val spotBook: String = DiesisAddresses.DIESIS_SPOT_BOOK
```

## Regenerate

**In short.** One script rebuilds every generated file from the contracts and
from `canonical.json`. A check mode tells you if anything is stale.

**Details.** `scripts/generate.py` needs only Python 3. It reads the compiled
contracts from `../../diesis-core/diesis/contracts/out` and runs that checkout's abi-typegen,
version 0.8.0 or newer. Set `DIESIS_CONTRACTS_DIR` or `ABI_TYPEGEN` to use a
different checkout or binary. It generates the bindings in the
`xyz.diesis.contracts` package, and writes `DiesisAddresses.kt`,
`DiesisChains.kt`, and `DiesisContracts.kt` from `canonical.json`. It copies
`canonical.json` from `../diesis-js` when that checkout is present.
`--check` changes nothing and exits non-zero if any generated file or
`canonical.json` differs from what the script would write.

```bash
python3 scripts/generate.py          # regenerate everything
python3 scripts/generate.py --check  # fail if anything is stale
```

Do not edit the generated files by hand. They are
`src/main/kotlin/xyz/diesis/contracts/*.kt`, `DiesisAddresses.kt`,
`DiesisChains.kt`, and `DiesisContracts.kt`.

## Develop

```bash
./gradlew test   # JUnit 5 tests, no network needed
./gradlew build  # compile, test, and package
```

The tests check addresses and chains against `canonical.json`, the contract
table, and the README examples. They parse every generated ABI with web3j and
check each signature, selector, and topic, and that each function, event, and
error with arguments has a generated class with matching fields. When the
contracts checkout is present, they also compare each generated ABI with the
contract artifact.
